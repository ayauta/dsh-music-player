## 结论

保留迷你播放器、封面网格与现有主题基础。最明显的体验损失来自可用空间分配、失效入口和内容身份；现有证据不支持整体重做。

当前窗口约 799×601 时，两层导航加上固定的次要列，几乎挤掉歌曲标题。最大化约 1920×1032 后恢复正常。这是本轮最直接的布局发现。尺寸为工具截图坐标范围，不冒充经过 DOM 测量的 CSS 内容尺寸或屏幕物理分辨率。

## 五个用户任务

1. 找歌：全部歌曲中文过滤和无结果提示正常；专辑总览过滤失效，工具能力与页面不匹配。
2. 浏览专辑：网格封面清楚、值得保留；进入单曲专辑后身份丢失、播放入口主要依赖双击或更多菜单。
3. 控制当前播放：播放/暂停、进度拖动与跨视图显示已观察；没有发现需要重写进度条的证据。动态流畅度未录屏定量评价。
4. 查看队列：现有完整列表可读，当前曲有底色；但入口转移主工作区、冗余工具与清空操作争夺注意力。真实拖排/移除手感未测，隔离 Host 操作覆盖不替代 UI 手感。
5. 管理来源：四来源与分组清楚；缺少可见的来源级最近扫描结果。没有在真实库执行扫描或来源增删，不能把静态页面观察写成“扫描成功反馈验收”。

## 保留与最小实施顺序

保留：宿主行式迷你播放器、真实封面网格、中性占位、主题 token、封面优先的浮层、常驻传输键、现有专辑/艺术家/文件夹入口。字体、圆角与动效具体数值没有在本轮获得批准。

建议按独立任务实施：

1. 交互可靠性：键盘边界与队列读取失败反馈分别处理，使用隔离行为测试；不扩到播放核心。
2. 可观察的 UI 缺陷：收藏空态、无效工具、规格入口分别验收；修复专辑标题。
3. 最有价值的视觉切片：歌曲列表容器响应式列宽，让歌名在窄窗仍可辨认，宽窗减少歌名到其他字段的大空隙。
4. 落实 R06；专辑紧凑内容头作为另一项设计提案，再决定尺寸、播放入口与留白。

暂不做整体导航重建、框架迁移、透明材质系统或动画库。尚未实现的缺失项/重新定位与扫描状态入口继续按既定路线处理。
