## 跑法

双击 `index.html`。零依赖、无服务、无构建（file:// 直接跑）。

状态都能用 URL 带走，方便贴给别人看：

```
index.html?variant=A&theme=dark&step=1000&inset=native&fill=smooth
```

| 参数 | 值 | 含义 |
|---|---|---|
| `variant` | `0` `A` `B` `C` | 0 = 现状对照（自绘）；A = 纯伪元素；B = accent-color；C = DOM 轨 + 平台滑块 |
| `theme` | `light` `dark` | 亮/暗两套 token |
| `step` | `1000` `250` `100` `any` | 键盘步进 = 控件值量化（同一个数，见下） |
| `inset` | `native` `full` | 填充止于滑块圆心（UA 行程）还是容器两端（今天的画法） |
| `fill` | `value` `smooth` | 填充跟控件值（与滑块同步）还是跟宿主插值（滑块最多落后一步） |

底栏 ‹ › 或 ← → 切换方案；**焦点在滑块上时方向键归滑块**（原型让路，这正是要验的 UA 行为）。

## 四个方案

| | 结构 | 取向 | 已知代价 |
|---|---|---|---|
| **0 现状** | `div` 轨 + `div` 填充 + `div` 滑块，`role="progressbar"` / `role="meter"` | 自绘，指针独占 | 不可聚焦、无键盘路径（SC 2.1.1）；`progressbar` 原文只读却可拖（B36）；气泡每帧写 |
| **A 纯伪元素** | 只有 `<input>`；轨/填充/滑块全在 `::-webkit-slider-runnable-track` / `-thumb` 上 | 最少 DOM，观感完全由控件自己画 | 每个 surface × 每个状态都要在伪元素上重写；填充是 `linear-gradient`（重绘，非合成层）；依赖非标准伪元素 |
| **B accent-color** | 只有 `<input>`，只给一个 `accent-color` | 最彻底地交给平台：1 次/秒写入、零伪元素、强制色/高对比天然正确 | UA 滑块 16px：迷你行 10px 会被顶破、设置行想"无滑块"做不到、没有拖动气泡；外观是另一族 |
| **C 双层** | `div` 轨 + `div` 填充（今天的画法）+ 透明交互层 `<input>`，滑块用 `::-webkit-slider-thumb` | 视觉自绘不变、交互全交平台；填充仍是合成层 | 两套几何要同步（行程盒 = 容器 − 半个滑块），多一层 DOM |

## 本页实测（headless Edge 157 / Blink，1140×980）

> DSH 桌面端是 Electron，Chromium 版本与 Edge 157 不完全相同：**这里的数字是"能测到的证据"，
> 不是规范**。L3 的四条判据仍要在真宿主上过一遍（UA 行为本来就只能实测，取证笔记 §1.3）。

| | 命中区 | 可聚焦 | 方向键 | Home/End | 播放中写入 | 暂停写入 |
|---|---|---|---|---|---|---|
| 0 现状 | 266×20 | ✗ | ✗ | ✗ | 60/s（真实代码再加气泡 = 120/s） | 0 |
| A `fill=smooth` | 266×20 | ✓ | ✓ +1s/按 | ✓ | 61/s | 0 |
| A `fill=value` | 266×20 | ✓ | ✓ | ✓ | 2/s | 0 |
| B | 266×20 | ✓ | ✓ | ✓ | 1/s | 0 |
| C `fill=smooth` | 266×20 | ✓ | ✓ | ✓ | 61/s | 0 |

四条 surface 的命中区（A/C 与今天一致）：面板进度 266×20、面板音量 230×18、迷你行 203×10、设置音量 124×18。

其它实测：

- **`step` 同时决定键盘步进和滑块量化**：`step=1000` 时滑块每次跳 1.24px（266px 宽、3:34 的曲子），
  `step=250` 时 0.31px。想要滑块丝滑只能把 `step` 调到 ≤100ms，代价是方向键按一次 0.1s（时间读数不变，看着像没反应）。
- `step="any"`：方向键**仍在动**，但步长由 UA 自己定（这里约 2.3s/按），不可设计 —— 已实测。
- 原生 range 的**命中区就是 input 的盒子**：点最左/最右分别得到 0 / max，没有死区。
- **两端 6px**：UA 的滑块行程是 `[6px, W−6px]`，今天自绘的滑块是 `[0, W]`（两端各探出半个滑块）。
  所以填充也必须跟着止于圆心，否则 p→1 时填充会比滑块多出 6px。
- 静止（暂停）时**零写入**：A/B/C/0 都是 0/s —— 原生控件把"值没变就不写"变成了结构上的保证（D-30）。

## 这个原型故意简化了什么

- 假宿主：1 Hz 采样 + 120ms seek 延迟 + 同形的闩锁；真实 `lib/shared/playhead.js` 的边界（时钟回拨、
  RTT 抖动）没有搬过来。
- 没有 host 命令队列：真实客户端每条命令都走 `command()` + `guarded()`，这里直接改本地对象。
- 没有读屏与强制色实测：只模拟了 `prefers-reduced-motion` 与"高对比"的轨道加粗。
- 气泡文案没有做零点吸附等细节。

## 两个已经踩到的坑（落地时必须处理）

1. **旧 seek 的盖章会提前放行新请求**：连按方向键时，前一次 seek 在宿主侧落地并盖章，
   会让"等宿主看见"的闩锁把后一次请求也放行，于是条会先退一下。需要"在途请求合并/定序"，
   与 D-32 的响应定序同源。
2. **rAF 回写 `value` 会吃掉键盘输入**：播放中每帧把宿主位置写回 `input.value`，
   在"用户刚按了键、宿主还没看见"的那几十毫秒里会把用户的值盖掉。规则应当是：
   **控件有焦点/有在途交互时，值归用户**。
